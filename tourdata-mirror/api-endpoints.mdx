## API base path

All data endpoints are mounted under `/api/v1` and require Entra JWT authentication. Health probes remain at `/health` and `/ready`. The API uses keyset pagination, read-only transactions, query timeouts, and per-endpoint or per-domain write feature flags.

```text
/api/v1
```

Use an Entra bearer token in the `Authorization` header when calling protected endpoints.

<CodeGroup show-lines="true">
  ```bash
  curl --request GET \
    --url https://tourdata-mirror.example.org/api/v1/trips \
    --header "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example.token"
  ```
</CodeGroup>

## Health

Health probes are available outside the `/api/v1` prefix and do not require the normal data API route prefix.

| Method | Path      | Description                               |
| ------ | --------- | ----------------------------------------- |
| `GET`  | `/health` | Liveness check with no database access.   |
| `GET`  | `/ready`  | Readiness check that executes `SELECT 1`. |

## Trips

Trip endpoints provide catalogue records, departure data, detailed trip information, realization data, and similar-trip recommendations.

| Method | Path                                  | Description                                                                                            |
| ------ | ------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `GET`  | `/api/v1/trips`                       | List trips with search, filters, sorting, and keyset pagination.                                       |
| `GET`  | `/api/v1/trips/departures`            | List trip departure dates and related departure information.                                           |
| `GET`  | `/api/v1/trips/{trip_id}`             | Return details for a trip.                                                                             |
| `GET`  | `/api/v1/trips/{trip_id}/realization` | Return representative booking and supplier or service realization data for a trip.                     |
| `GET`  | `/api/v1/trips/{trip_id}/similar`     | Return similar trips based on catalogue attributes such as categories, countries, price, and duration. |

## Bookings

Booking endpoints expose mirrored dossier data and derived operational views.

| Method | Path                                   | Description                                                            |
| ------ | -------------------------------------- | ---------------------------------------------------------------------- |
| `GET`  | `/api/v1/bookings`                     | List bookings with filtering, sorting, and pagination.                 |
| `GET`  | `/api/v1/bookings/stats`               | Return booking statistics.                                             |
| `GET`  | `/api/v1/bookings/departure-crew`      | Return crew assigned to a booking departure.                           |
| `GET`  | `/api/v1/bookings/manifest`            | Return the participant manifest, including resolved participant roles. |
| `GET`  | `/api/v1/bookings/{booking_id}`        | Return details for a booking.                                          |
| `GET`  | `/api/v1/bookings/{booking_id}/graph`  | Return the booking graph and related entities.                         |
| `GET`  | `/api/v1/bookings/{booking_id}/hotels` | Return hotel services and overnight stays for a booking.               |

## Reference data

Use the reference endpoints to retrieve shared lookup data used by trips, bookings, and feedback consumers.

| Method | Path                       | Description                                                                                                                                                           |
| ------ | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/v1/reference`        | Return the available reference-data collections.                                                                                                                      |
| `GET`  | `/api/v1/reference/{kind}` | Return one reference-data collection. Supported kinds include `countries`, `service-types`, `trip-categories`, `tenants`, `sales-agents`, `questions`, and `choices`. |

## Aggregates

The aggregate API is intended for dashboards and BI consumers that need measures and dimensions rather than individual records.

| Method | Path                                  | Description                                                                       |
| ------ | ------------------------------------- | --------------------------------------------------------------------------------- |
| `GET`  | `/api/v1/aggregates`                  | Describe available aggregate datasets, measures, dimensions, and access metadata. |
| `POST` | `/api/v1/aggregates/{dataset}/query`  | Query a dataset with time-range and dimension filters.                            |
| `GET`  | `/api/v1/aggregates/{dataset}/values` | Return available values for a dataset dimension.                                  |

Aggregate responses can include provenance, an `as of` timestamp, cursors, and caching metadata. Dataset access, minimum-group suppression, query timeouts, and rate limits apply.

## Velo

Velo endpoints expose trip and departure application state. Write operations are controlled by `VELO_WRITE_ENABLED`.

| Method   | Path                                                               | Description                                                     |
| -------- | ------------------------------------------------------------------ | --------------------------------------------------------------- |
| `GET`    | `/api/v1/velo/status`                                              | Return Velo service or application status.                      |
| `GET`    | `/api/v1/velo/trips/{trip_code}/{departure}/appdata`               | Return Velo application data for a trip departure.              |
| `PUT`    | `/api/v1/velo/trips/{trip_code}/{departure}/status`                | Update the status of a trip departure.                          |
| `PUT`    | `/api/v1/velo/trips/{trip_code}/{departure}/meta`                  | Update trip departure metadata.                                 |
| `PUT`    | `/api/v1/velo/trips/{trip_code}/{departure}/buses/{bus}/anhaenger` | Add or update a trailer or replacement bicycle entry for a bus. |

| `POST`   | `/api/v1/velo/trips/{trip_code}/{departure}/prints`                | Record a print cycle for a trip departure.                      |

## kd-doc

Authenticated kd-doc endpoints store and retrieve scoped JSON documents and content-addressed assets. Writes are controlled by `KD_DOC_WRITE_ENABLED`.

| Method   | Path                           | Description                                      |
| -------- | ------------------------------ | ------------------------------------------------ |
| `GET`    | `/api/v1/kddoc`                | List document keys or IDs.                       |
| `GET`    | `/api/v1/kddoc/{scope}/{key}`  | Return a document by scope and key.              |
| `PUT`    | `/api/v1/kddoc/{scope}/{key}`  | Create or replace a document.                    |
| `DELETE` | `/api/v1/kddoc/{scope}/{key}`  | Delete a document.                               |
| `GET`    | `/api/v1/kddoc/asset`          | List available content-addressed assets.         |
| `PUT`    | `/api/v1/kddoc/asset/{sha256}` | Upload or store an asset by SHA-256 hash.        |
| `POST`   | `/api/v1/kddoc/link`           | Create a public customer-document link.          |
| `POST`   | `/api/v1/kddoc/link/revoke`    | Revoke a public customer-document link.          |
| `GET`    | `/api/v1/kddoc/published`      | Retrieve a published document by Dossier number. |

### Public kd-doc endpoints

Public customer-link endpoints do not use Entra authentication. They validate the link signature and expiry, enforce revocation checks, and apply rate limits.

| Method | Path                                          | Description                                                                               |
| ------ | --------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `GET`  | `/api/v1/kddoc/public/{token}`                | Return the document associated with a public link token.                                  |
| `GET`  | `/api/v1/kddoc/public/{token}/aktuell`        | Return the current document view, including applicable boarding-location or time changes. |
| `GET`  | `/api/v1/kddoc/public/{token}/asset/{sha256}` | Return a content-addressed asset associated with a public document link.                  |
