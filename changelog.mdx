## Recent Updates

Stay informed about the latest improvements across TWG's travel technology platform. This changelog highlights product updates, API changes, analytics improvements, and fixes that affect travel applications and internal workflows.

Subscribe to our RSS feed or GitHub notifications to get changelog updates automatically.

<Update label="2026-10-08" description="TourData Mirror" tags={["feature", "improvement"]}>

## Aggregate API enhancements

- Added `full_days`, `half_days`, and `operating_days` measures to the `vehicle_days` dataset for explicit half-day and full-day classification.
- Expanded `staff_days` to include drivers and vehicle crew, with filterable `role`, `category`, and `vehicle` dimensions.
- Increased the `vehicle_days` query limit to 366 days when using the `day` dimension, supporting full annual time series.
- Made vehicle downtime calculations available without the personal-aggregate permission flag.

## Disposition and trip linking

- Disposition-to-trip association now follows three-level precedence: the planned trip from the API, majority-dossier matching, then exact title or code fallback.
- Disposition conflicts, including duplicate assignments and absence conflicts, now return HTTP 409 with JSON details instead of HTTP 500.

## Feedback and booking aggregates

- Standardized `avg_rating` calculations with feedback rating logic by normalizing quality words and numeric scales.
- Added the `pax` measure to departures and bookings datasets. The measure counts every person represented by a booking, including group bookings.
- Bookings without a status dimension or filter now return only non-cancelled bookings by default.
- Aggregate responses now include human-readable labels for brands, trips, countries, categories, and questions.
- Destination country values now use ISO 3166-1 alpha-2 codes instead of numeric IDs.

## MCP tools

- Added `list_aggregates`, `query_aggregates`, and `aggregate_values` MCP tools for aggregate datasets.
- Added the `get_departure_dispositions` MCP tool, which returns vehicles, trailers, drivers, and tour leaders.
- Added `format="analytics"` for chart-oriented MCP responses with typed columns, units, and labels.
- Expanded remote MCP to expose all internal tools, gated by Entra group membership.

## Data sync

- Trips departing within seven days and currently running now refresh every 30 minutes during business hours in the development environment.
- The aggregate values endpoint no longer requires both date bounds. Omitted dates now default to a one-year window.

</Update>

<Update label="2026-09-30" description="Review Analytics" tags={["feature", "improvement"]}>

## Questionnaire analytics

- Multiple-choice selection masks are now decoded across tenants, surfacing previously missing guest-profile answers.
- Yes/no questions are now aggregated and displayed with percentages and sample sizes.
- Increased the questionnaire analytics cap from 30 to 250 questions.
- Added support for grouping questions into questionnaire-defined sections with per-section averages.

## Dashboard improvements

- Added year-over-year comparisons with delta indicators and decline warnings for question groups.
- Added Top and Flop trips analysis, ranking trips by NPS or average rating with minimum response count filters.
- Reviews can now be viewed by question as well as by guest.
- Review details now display the dossier number.
- Added predefined PDF report prompts to the Copilot panel, organized into Reports, Themes, Questionnaire, Freetext, and Trend groups.

## UI redesign

- Introduced a common application shell with a shared top bar across dashboard and trip pages.
- Moved dashboard filters to a dedicated filter bar with active filter chips and overflow handling.
- Unified trip selection. Clicking a row applies the trip as a filter, while the external icon opens the trip dashboard.
- Standardized line icons, color tokens, and Swiss spelling throughout the interface.

## Bug fixes

- Restored missing `/api/v1/alerts/*` routes that caused alert rule editing to fail.
- Upstream API errors now retain their original status codes instead of being converted to generic 503 responses.

</Update>

<Update label="2026-09-30" description="KD Dossier" tags={["feature", "improvement", "bugfix"]}>

## PDF export

- PDF exports now inherit the same document state as the editor, including travel-level and departure-level changes.
- Saved dossiers now refresh with current booking data before export, preventing stale passenger, time, and departure information.
- Departure locations are now dossier-specific and use each booking's boarding location instead of the trip's first departure point.
- Arrival text now references the booked departure location.

## Export validation

- Cross-tenant export attempts now return HTTP 403 instead of generating documents with the wrong brand.
- Single-booking exports for bookings outside the initial load now resolve correctly.
- Invalid export requests now return meaningful error messages instead of empty PDFs or generic 503 responses.

## Editor

- Deleted sections can now be restored after reloading and are inserted in their original position.
- Block actions now target blocks by stable engine key, preventing edits to the wrong blocks when hidden or grouped blocks shift positions.
- The PDF header now places dossier and customer numbers consistently with the editor layout.

</Update>

<Update label="2026-09-30" description="Fullstack Starter" tags={["feature", "breaking"]}>

## Shared components

- Added entity notes for notes shared across TWG applications. Notes can attach to bookings, trips, and customers and support create, edit, delete, and mark-as-important actions.
- Added an app switcher with a cross-application navigation menu and environment-aware URLs.
- Added a reusable user menu for displaying user identity and logging out.

## API versioning

Domain API endpoints moved from `/api/...` to `/api/v1/...`. Migrate callers using `/api/notes` to `/api/v1/notes`.

<Callout kind="alert">

Update integrations that call unversioned domain endpoints before deploying this release. Requests to `/api/notes` must use `/api/v1/notes`.

</Callout>

## Authentication

- Silent session renewal now recovers from expired tokens by redirecting to interactive login instead of leaving users with a dead session.
- Centralized AI model and prompt configuration through optional Mirror integration, with environment-variable and code-level fallbacks.

## Migration steps
