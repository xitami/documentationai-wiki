<Update label="2026-09-30" description="kd-doc v1.0.0 (in progress)" tags={["feature","improvement"]}>
  ## Editor

  - Deleted document sections can now be recovered after page reload. The "N blocks removed" panel persists, and restored blocks return to their original position in the template.
  - Content insertion (⊕), AI text, and photo upload now target the correct block via engine key instead of position counting, fixing misplacement when hidden or bundled blocks shifted indices.
  - Hidden blocks that are suppressed by rules are now bundled into a compact "N blocks hidden" row instead of showing gray placeholders individually.

  ## PDF Export

  - Dossier PDFs now inherit trip and departure versions exactly as the editor renders them. Previously, saved documents without their own version went to PDF fresh from the template, missing trip- and departure-level changes.
  - Per-dossier departure location, time, and customer address are pulled from the Mirror, replacing the previous behavior of showing the first list location for all dossiers.
  - Dossier and customer numbers are placed in the document header, matching the editor layout.
  - Booklet covers (A5 print) are now available in brand look for seven trip types: flight, bike, e-mountainbike, winter, bus, music, and river cruises.
  - Tenant validation prevents an Imbach trip from being exported with the Twerenbold brand. The export returns 403 with the correct brand name.

  ## Brand CD

  - House colors and fonts now follow brand guidelines: Excellence uses gold and purple, Vögele uses dark and light green, and Imbach uses dark and light blue. Each brand now has an `accent2` color and embedded web fonts in PDF.

  ## New Document Blocks

  - "Ihre Sitzplätze im Reisebus" provides bus seat assignments with each passenger's name and seat number, plus a bus label for multi-bus departures.
  - "Ihre Flüge" provides flight segments with dates, routes, times, aircraft, baggage, and PNR. Amadeus itinerary import via text or PDF paste is merged with Mirror data.
  - A "Check-in" section for flight trips provides check-in times, calculated as two hours before departure, with the airline, flight number, and airport.

  ## Mirror Integration

  - Postal address from Mirror customer master sync (`customer_address` / `address`) replaces handwritten names with structured address data (VBCD-182).
  - Travel club members no longer see the invitation block (VBCD-183).
</Update>

<Update label="2026-09-28" description="tourdata-mirror v0.4.0" tags={["feature","improvement"]}>
  ## New Features

  - **Aggregate API**: Self-describing read-only analytics datasets with query and values endpoints, filtering, dimensions, pagination, ETags, rate limiting, minimum-group suppression, and caller-specific access policies. Covers bookings, feedback, staff days, and vehicle days.
  - **Event Pipeline**: CloudEvents and webhook contracts, per-endpoint subscriptions, HMAC signing, DNS and SSRF protection, fan-out, lane ordering, retries, backoff, dead-letter handling, and a development console mode.
  - **Alert System**: Rule-based alerts with metrics, dry runs, activation safeguards, trigger history, deduplication and re-arm logic, JSON-defined metric packs, admin UI, MCP tools, previews, and histogram data for threshold selection.
  - **Alert Channels & Inbox**: Alerts are integrated with the event pipeline for mail, webhook, and in-app inbox notifications. Users can subscribe, mute, read, acknowledge, and snooze alert items.
  - **MCP Analytics**: Aggregate API tools with chart block output format. The remote MCP profile includes Entra token validation, group-based authorization, token-derived identity, audit logging, and protected-resource metadata.
  - **Personnel Sync**: Authoritative personnel dimension from expanded Disposition and Address APIs with stable person IDs, source-mandant mapping, full personnel-list reconciliation, and status-9 deletion handling.
  - **Customer Master Sync**: Scheduled Container Apps job for customer addresses, document-delivery preferences, and travel-club membership. Read APIs now expose customer address and club information without per-booking calls.

  ## Improvements

  - Trip hashes now cover only mirrored columns, avoiding spurious `trip.changed` events.
  - Failed WebTrip detail requests no longer delete existing departure dates.
  - Dossier survey pages are recursively salvaged after upstream HTTP 500 responses.
  - CSV-created personnel are deactivated when absent from the authoritative personnel list.
  - Feedback ratings are normalized and precomputed to avoid expensive JSONB scans. Destination countries are converted to ISO codes, and `pax` is added for group bookings.
  - Production operations now include reliable migration-job polling during releases, CORS and origin configuration, enabled mail and dispo write gates, and always-on replicas restored after cold-start issues.

  ## Breaking Changes

  - `DISPO_WRITE_ENABLED=true` is required for production RL-disposition writes.
  - `KD_DOC_WRITE_ENABLED=true` is required for production kd-doc persistence.
  - `MAIL_SEND_ENABLED=true`, Graph credentials, and an authorized sender are required for production mail.
  - Event delivery requires `EVENTS_TRANSPORT=http` and endpoint secrets.
</Update>

<Update label="2026-08-28" description="tourdata-mirror v0.2.0" tags={["feature"]}>
  ## New Features

  - **Disposition Module**: The `dispo` schema provides application-owned planning data, raw `tourdata.dispo_*` source tables, matching rules, staffing requirements, planning runs, proposals, and decision logs.
  - **RL-Dispo Portal**: Self-service preferences, languages, qualifications, desired months, avoided trips, self-imposed capacity limits, Magic Links, decision history, and trainee-guide roles.
  - **Mail Service**: Centralized Mirror mail service with sender authorization, idempotency keys, outbox, delivery log, retry and backoff, PII retention, Graph transport, templates, branded HTML layouts, admin dashboard, and MCP `send_mail` tool.
  - **kd-doc Pipeline**: Signed public document delivery without Entra login, HTML and JSON content negotiation, rate limiting, individual link revocation, content-addressed image storage, and bundled customer viewer.
  - **Entity Notes & Graph Navigation**: Shared `workspace.entity_note` model and CRUD API for notes attached to bookings, trips, and customers. Generic entity graph API and MCP tools support cross-entity navigation.
  - **MCP**: The `describe_schema` tool supports ad-hoc SQL column discovery instead of guessing.

  ## Improvements

  - Multi-tenant sync now uses tenant-specific cursors and missing-credential isolation, preventing one tenant failure from stopping others.
  - Booking data now includes participant boarding information, crew phone numbers, and a hotel endpoint with nights and supplier addresses.
  - Feedback now includes theme aspects, voices, and departure-specific filtering.

  ## Infrastructure

  - The release path was repaired. `build-image` now needs `environment` for OIDC authentication on tag-based deploys.
  - Azure Functions deployment workflow now installs Core Tools reliably.
  - Pre-push CI now runs a replica of repository checks.

  ## Breaking Changes

  - The MCP dependency is capped below v2.0. MCP 2.0 removed `mcp.server.fastmcp`, which crashed the MCP container.
</Update>

<Update label="2026-07-26" description="tourdata-mirror v0.1.0" tags={["feature"]}>
  ## Initial Release

  - **Mirror Pipeline**: Dossier-API and Web-Trip-API data is mirrored into PostgreSQL with resumable, idempotent upserts, auth refresh, and ASC-cursor-sync. Data levels 1–3 include bookings, persons, participants, invoices, services, service items, and business partners.
  - **Read-API**: FastAPI with Entra Bearer auth stub, Debug UI at `/debug`, and `list_bookings` with `dsid` filtering for exact dossier numbers and deep links.
  - **MCP Server**: Read-only stdio server with 20 tools over the Read-API, including `get_trip_departures`, `get_booking_stats`, `search_bookings` (non-PII), `get_booking_manifest`, `get_customer`, and `get_customer_bookings` (PII, gated via Orchestrator manifest).
  - **Azure Terraform**: Private-by-default infrastructure with Postgres Flex VNet integration, Key Vault and Storage with Private Endpoints, Function EP1 VNet integration, Container Apps environment, Log Analytics, App Insights, and alerts.
  - Live verification against production covered 2,719 bookings, 12,240 services, and 187 enriched trips. The release included 149 passed tests and 22 skipped tests.
</Update>

## Upgrading Between Versions

| --------------- | --------------------------------------------- | ---------------- |

| v0.4.2          | Portal "in planning" trips                    | Low              |
| v0.2.0          | Disposition, mail, kd-doc, entity notes       | High             |

| v0.1.0          | Initial mirror pipeline + Read-API + MCP      | —                |

## Contributing to the Changelog

Releases are tagged with `vX.Y.Z` on the main branch. TourData Mirror and kd-doc auto-generate GitHub Releases via CI. To add an entry, tag a release and the changelog will be updated in the next sync. Found an issue? Submit a pull request against the relevant repository.
