## TWG platform capabilities

The TWG platform provides data mirroring, analytics, disposition planning, document management, alerting, event delivery, and LLM-accessible read APIs. Each capability is backed by a dedicated schema and exposed through the FastAPI application or scheduled jobs.

## Feature Matrix

| Feature | Primary schema | Access mode |
|---|---|---|
| TourData Mirroring | `tourdata` | Read via API / Write via sync |
| Feedback Analytics | `feedback_analytics` | Read via API / Write via ingest jobs |
| Disposition Planning | `dispo` | Read + Write via API |
| Velo-Log | `velo_log` | Read + Write via API, gated |
| kd-doc | `kd_store` | Read + Write via API, gated |
| Alerts | `alert` | Read + Write via API and job |
| Events | `event` | Read catalog / Write via sync and job |
| Aggregates API | Read models | Read-only |
| MCP Server | All domains | Read-only |
| Mail | `mail` | Write on submit + Read for status |

<Callout kind="info">

Source-owned data in `tourdata` is refreshed by ingestion and remains read-only for applications. Application-owned schemas, including `dispo`, `velo_log`, `kd_store`, `mail`, `alert`, and `event`, support writes through their respective API boundaries.

</Callout>

## Multi-Tenant Architecture

TWG keeps each tenant isolated across credentials, synchronization runs, and domain data. Configured tenants include `twr`, `imb`, `rmt`, `voe`, and `exc`.

Tenant identity is part of the data model. A trip is identified by `(tenant_id, trip_code)`, so the same trip code may exist in more than one tenant without creating a collision.

<Callout kind="tip">

Always include the tenant when querying or storing trip-related data. Trip codes are not globally unique across the platform.

</Callout>

## Write Protection

The platform gates selected write paths with explicit configuration flags. Keep these flags disabled unless the corresponding application boundary is ready to write data.

<ParamField body="VELO_WRITE_ENABLED" param-type="boolean" show-location="false">
  Enables writes for the Velo-Log API and its `velo_log` data.
</ParamField>

<ParamField body="KD_DOC_WRITE_ENABLED" param-type="boolean" show-location="false">
  Enables writes for the kd-doc API and its `kd_store` data.
</ParamField>

<ParamField body="READ_API_AGGREGATES_PERSONAL" param-type="boolean" show-location="false">
  Enables personal-related aggregate datasets, including `guide_ratings` and the person dimension in `staff_days`.
</ParamField>

<Callout kind="alert">

Production startup fails closed when the Microsoft Entra tenant or API audience configuration is missing. Configure Entra authentication before enabling production API access.

</Callout>
