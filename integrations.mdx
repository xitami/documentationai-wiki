## Integration Landscape

The TWG platform integrates with external systems across four layers: upstream data sources, identity and mail services, LLM providers, and downstream consumers. Each integration is configured through environment variables in `config.py` and documented in the [configuration reference](tourdata-mirror/configuration).

## Upstream Data Sources

The mirror ingests data from four TourData APIs. Each source is authenticated per-tenant, and ingestion runs as resumable, idempotent upserts into PostgreSQL.

| API                | Configuration               | Data                                                | Sync Module           |
| ------------------ | --------------------------- | --------------------------------------------------- | --------------------- |
| Web Trip API       | `TOURDATA_WEBTRIP_BASE_URL` | Trips, departures, realizations                     | `sync/trips.py`       |
| Dossier API        | `TOURDATA_DOSSIER_BASE_URL` | Bookings, persons, participants, invoices, services | `sync/bookings.py`    |
| Disposition API v2 | `TOURDATA_DISPO_BASE_URL`   | Staff, assignments, planning runs, proposals        | `sync/dispo_staff.py` |
| Address API        | `TOURDATA_ADDRESS_BASE_URL` | Personnel, contacts, source-mandant mapping         | `sync/persons.py`     |

Tenant-specific credentials are resolved via `TOURDATA_<TENANT>_DOSSIER_USERNAME`, `TOURDATA_<TENANT>_DOSSIER_PASSWORD`, `TOURDATA_<TENANT>_WEBTRIP_USERNAME`, and `TOURDATA_<TENANT>_WEBTRIP_PASSWORD`. A tenant without credentials for one API is skipped during that API's sync run rather than aborting the entire job.

<Callout kind="info" collapsed="false">
  The nightly Azure Function at `functions/nightly_sync/__init__.py` runs at 02:00 UTC and processes all configured tenants independently. CLI tools (`tdm-backfill`, `tdm-ingest`) invoke the same sync modules for manual or initial backfills.
</Callout>

## Microsoft Entra ID

The Read API authenticates all `/api/v1` endpoints with Microsoft Entra ID (Azure AD) JWT bearer tokens. Health probes (`/health`, `/ready`) and public kd-doc links are exempt.

| Variable             | Purpose                                                  |
| -------------------- | -------------------------------------------------------- |
| `ENTRA_TENANT_ID`    | Entra tenant ID for token validation                     |
| `ENTRA_API_AUDIENCE` | Expected token audience, such as `api://tourdata-mirror` |

Production startup fails closed when Entra configuration is missing. In local development, the API runs with a debug stub that accepts any bearer token at `/debug`.

<Callout kind="alert" collapsed="false">
  Remote MCP access also validates Entra tokens with group-based authorization. See the [MCP Server documentation](tourdata-mirror/mcp-server) for remote profile configuration.
</Callout>

## Microsoft Graph (Mail)

The mail service sends outbound email through Microsoft Graph when `MAIL_TRANSPORT=graph`. Messages are rendered and stored before delivery; retries use the stored rendered message rather than re-rendering.

| Variable                   | Purpose                                            |
| -------------------------- | -------------------------------------------------- |
| `MAIL_GRAPH_TENANT_ID`     | Entra tenant ID for Graph client credentials       |
| `MAIL_GRAPH_CLIENT_ID`     | App registration client ID                         |
| `MAIL_GRAPH_CLIENT_SECRET` | App registration client secret                     |
| `MAIL_ALLOWED_RECIPIENTS`  | Recipient allowlist for development safety         |
| `MAIL_SEND_ENABLED`        | Master switch, defaulting to `false` in production |

In development, `MAIL_TRANSPORT=console` logs messages to stdout instead of sending them.

## LLM Providers

Feedback enrichment, sentiment analysis, and trip recommendations use OpenAI-compatible LLM providers. The platform supports OpenRouter as the primary provider with an Anthropic-compatible fallback.

| Variable                    | Purpose                                                |
| --------------------------- | ------------------------------------------------------ |
| `OPENROUTER_API_KEY`        | API key for OpenRouter                                 |
| `ANTHROPIC_API_KEY`         | API key for Anthropic fallback                         |
| `LLM_BASE_URL`              | Base URL for the OpenAI-compatible provider            |
| `ANTHROPIC_OPENAI_BASE_URL` | Base URL for the Anthropic OpenAI-compatible interface |
| `ANTHROPIC_MODEL`           | Model for general LLM tasks                            |
| `ANTHROPIC_MODEL_SENTIMENT` | Model for sentiment processing                         |

The AI configuration catalog, available at the `/api/v1/ai/models` endpoint, manages model versions, task assignments, and version history for sentiment, recommendations, assistant, and kd-doc generation.

## MCP (Model Context Protocol)

The MCP server exposes the mirror's data to LLM clients such as Claude Code, Claude Desktop, and other MCP-compatible tools. It offers 20+ read-only tools covering trips, bookings, feedback, aggregates, alerts, and reference data, plus controlled write tools for notes, mail, and alert rules.

The server supports two modes:

- **Local stdio** (`tdm-mcp`): For Claude Code and local MCP clients.
- **Remote HTTP** (`tdm-mcp-http`): Entra-authenticated with group-based authorization, token-derived identity, audit logging, and protected-resource metadata.

<Callout kind="tip" collapsed="false">
  The MCP dependency is capped below v2.0. MCP 2.0 removed `mcp.server.fastmcp`, which would crash the MCP container. See the [MCP Server documentation](tourdata-mirror/mcp-server) for setup and the full tool list.
</Callout>

## Event Pipeline and Webhooks

The event pipeline delivers CloudEvents to registered webhook endpoints with HMAC-SHA256 signing, per-endpoint subscriptions, lane ordering, retries, backoff, and dead-letter handling.

| Variable                 | Purpose                                                            |
| ------------------------ | ------------------------------------------------------------------ |
| `EVENTS_TRANSPORT`       | Transport mode: `console` for development or `http` for production |
| `EVENTS_DELIVER_ENABLED` | Master switch for event delivery                                   |
| `EVENTS_ALLOWED_HOSTS`   | Host allowlist for outbound delivery and DNS or SSRF protection    |

Alert rules can trigger notifications through three channels: mail, webhook as filtered event subscriptions, and in-app inbox. See the [Events and Webhooks documentation](tourdata-mirror/events) and the [Alerts documentation](tourdata-mirror/alerts) for subscription and channel configuration.

## kd-doc Public Links

Customer documents can be delivered via signed public links without Entra authentication. The service validates token signature, expiry, document scope, revocation status, and rate limits.

| Variable                        | Purpose                                |
| ------------------------------- | -------------------------------------- |
| `KDDOC_LINK_SECRET`             | HMAC-SHA256 signing secret             |
| `KDDOC_PUBLIC_RATE_LIMIT`       | Maximum requests per rate-limit window |
| `KDDOC_PUBLIC_RATE_WINDOW_S`    | Rate-limit window in seconds           |
| `KDDOC_PUBLIC_ASSET_RATE_LIMIT` | Maximum asset requests per window      |

Links support HTML and JSON content negotiation, individual revocation, and content-addressed image storage. See the [data models page](tourdata-mirror/data-models) for the `kd_store` schema.

## Azure Infrastructure

The platform runs on Azure with private-by-default infrastructure. All services are VNet-integrated; secrets live in Key Vault; observability is handled by Log Analytics and Application Insights.

| Service                        | Purpose                                            |
| ------------------------------ | -------------------------------------------------- |
| Azure PostgreSQL Flex          | Mirror database, VNet-integrated                   |
| Azure Container Apps           | Read API runtime and sync jobs with image rotation |
| Azure Functions                | Nightly sync at 02:00 UTC                          |
| Azure Key Vault                | Secrets per environment, with Private Endpoints    |
| Azure Storage                  | Content-addressed assets with Private Endpoints    |
| Log Analytics and App Insights | Logging, metrics, and alerting                     |

Infrastructure is managed via Terraform in `infra/terraform/` with separate `dev.tfvars` and `prod.tfvars`. CI/CD runs through GitHub Actions with OIDC-based authentication. Tag-based deploys (`v*`) trigger the release workflow.
