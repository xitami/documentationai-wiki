## Overview

TWG products integrate through shared infrastructure and standard protocols. Applications connect to TourData Mirror through REST APIs and MCP tools, authenticate through Microsoft Entra ID, share data through entity notes, and centralize AI model configuration through an optional Mirror integration.

## MCP tools

TourData Mirror exposes internal tools through the Model Context Protocol. MCP clients can query aggregate datasets, retrieve disposition details, and format responses for visualization.

| Tool | Description |
| --- | --- |
| `list_aggregates` | List available aggregate datasets and their supported dimensions and measures. |
| `query_aggregates` | Query a dataset by measures, dimensions, filters, and date bounds. |
| `aggregate_values` | Retrieve valid values for dimensions such as brands, trips, countries, and categories. |
| `get_departure_dispositions` | Return vehicles, trailers, drivers, and tour leaders for a trip and departure date. |

Use `query_aggregates` with `format` set to `analytics` when the response will be consumed by an analytics or visualization client.

<CodeGroup tabs="JSON">

```json
{
  "tool": "query_aggregates",
  "arguments": {
    "dataset": "vehicle_days",
    "measures": [
      "full_days",
      "half_days",
      "operating_days"
    ],
    "dimensions": [
      "month",
      "brand"
    ],
    "from": "2025-01-01",
    "to": "2025-12-31",
    "format": "analytics"
  }
}
```

</CodeGroup>

<Callout kind="info">

Remote MCP exposes all internal tools to members of configured Entra groups. Identity fields come from the verified token, and remote calls are logged with the user OID, tool name, and result.

</Callout>

## REST API

Domain API endpoints are versioned under `/api/v1/`. The versioned prefix reserves `/api/v2/` for future breaking changes.

| Endpoint | Method | Purpose |
| --- | --- | --- |
| `/api/v1/notes` | GET, POST, PATCH, DELETE | Create, read, update, and delete entity notes. |
| `/api/v1/aggregates` | GET | List available aggregate datasets. |
| `/api/v1/aggregates/{dataset}/query` | POST | Query a dataset by measures and dimensions. |
| `/api/v1/aggregates/{dataset}/values` | GET | Retrieve valid values for a dataset's dimensions. |

<Callout kind="alert">

Domain endpoints moved from `/api/...` to `/api/v1/...`. Update integrations that call unversioned paths.

</Callout>

## Entra ID auth

TWG applications authenticate through Microsoft Entra ID, formerly Azure AD, using MSAL. Sessions renew silently in the background. When silent renewal fails because a token expired, the application redirects to interactive login instead of leaving the user with an inactive session.

<Expandable title="Token recovery behavior">

When the SPA refresh-token lifetime expires, the MSAL error code `timed_out` triggers a redirect to interactive login. Users do not need to manually log out and log back in after returning to the application the next day.

</Expandable>

## Entity notes

Entity notes are shared across TWG applications and can be attached to bookings, trips, and customers. Each note supports create, edit, delete, and mark-as-important actions, with author and timestamp metadata.

<Steps>
  <Step title="Set the entity context">

  The host application calls `twgShell.setEntityContext({ type, key })` to identify the entity associated with the notes view.

  </Step>
  <Step title="Normalize the entity key">

  TWG normalizes entity keys to their canonical form. For example, booking identifiers are converted to DSID format.

  </Step>
  <Step title="Use the notes API">

  The notes API exposes `GET`, `POST`, `PATCH`, and `DELETE` operations at `/api/v1/notes`.

  </Step>
  <Step title="Render notes in the host application">

  Notes can display with optional attached UI cards. Without a card renderer, TWG displays the Markdown content as a fallback.

  </Step>
</Steps>

## App switcher

The app switcher provides a cross-application navigation menu with environment-aware URLs. It detects the current environment from the hostname and can filter visible applications using an allowed-app list.

<Expandable title="Configuration">

The component supports these optional attributes:

- **`current`**: Highlights the active application.
- **`allowed`**: Filters the application list.
- **`env`**: Overrides environment detection.
- **`apps`**: Supplies a custom application registry.

In development, omitting `allowed` shows all registered applications.

</Expandable>

## AI configuration

Applications that include LLM functionality can centralize AI model and prompt configuration through an optional TourData Mirror integration. Settings resolve in this order: Mirror settings first, environment variables second, and code-level defaults last.

If Mirror is unavailable or unconfigured, the application continues using its previous fallback behavior. Settings are cached for five minutes.

<Callout kind="tip">

Register the model and prompt at the code level before configuring Mirror overrides. The application uses those registered values as the fallback when Mirror does not provide a setting.

</Callout>
