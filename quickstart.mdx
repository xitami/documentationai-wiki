## Prerequisites

Before starting, ensure you have the following installed:

- Python 3.12 or later
- Docker (for local PostgreSQL)
- Git
- TourData API credentials (Dossier and Web Trip username/password for at least one tenant)

<Callout kind="info" collapsed="false">
  No Azure subscription is needed for local development. The mirror runs entirely against a local PostgreSQL instance.
</Callout>

## Set Up the Project

<Steps>
  <Step title="Clone the repository" icon="github" title-type="p">
    Clone the TourData Mirror repository to your local machine.

    ```bash
    git clone https://github.com/twerenbold-group/twg-tourdata-mirror.git
    cd twg-tourdata-mirror
    ```
  </Step>

  <Step title="Create a virtual environment" icon="package" title-type="p">
    Set up a Python 3.12 virtual environment and install the package with development dependencies.

    ```bash
    python3.12 -m venv .venv
    source .venv/bin/activate
    pip install -e ".[dev]"
    ```
  </Step>

  <Step title="Start a local PostgreSQL" icon="database" title-type="p">
    The mirror uses PostgreSQL 16. Start a local instance via Docker. Port 5433 avoids conflicts with other projects.

    ```bash
    docker run --name tdm-pg \
      -e POSTGRES_USER=tdm \
      -e POSTGRES_PASSWORD=tdm \
      -e POSTGRES_DB=tourdata_mirror \
      -p 5433:5432 \
      -d postgres:16
    ```
  </Step>

  <Step title="Configure environment" icon="settings" title-type="p">
    Copy the example environment file and fill in your TourData API credentials and database URL.

    ```bash
    cp .env.example .env
    ```

    Open `.env` and set at minimum:

    - `DATABASE_URL`: Your local PostgreSQL connection string
    - `TOURDATA_TENANTS`: Comma-separated tenant identifiers, such as `twr`
    - `TOURDATA_<TENANT>_DOSSIER_USERNAME` and `TOURDATA_<TENANT>_DOSSIER_PASSWORD`: Your TourData credentials
    - `TOURDATA_<TENANT>_WEBTRIP_USERNAME` and `TOURDATA_<TENANT>_WEBTRIP_PASSWORD`: Your Web Trip credentials

    <Callout kind="alert" collapsed="false">
      For local development, Entra authentication can be left unconfigured. The Read API runs with a debug stub that accepts any bearer token. Production requires a valid `ENTRA_TENANT_ID` and `ENTRA_API_AUDIENCE`.
    </Callout>
  </Step>
</Steps>

## Apply Migrations

Run the migration CLI to create all database schemas: `tourdata`, `dispo`, `velo_log`, `kd_store`, `mail`, `alert`, `event`, and `feedback_analytics`.

```bash
tdm-migrate up
```

## Backfill Data

Run an initial backfill to populate the mirror with data from TourData. Start with trips, then bookings. Each command fetches from the upstream API and upserts into PostgreSQL.

```bash
tdm-backfill trips
tdm-backfill bookings
```

<Callout kind="tip" collapsed="false">
  Backfills are resumable and idempotent. If a run is interrupted, re-running the command picks up where it left off using ASC cursor tracking.
</Callout>

## Start the Read API

Launch the FastAPI Read API locally with hot reload. The API is available at `http://localhost:8000` with a debug UI at `/debug`.

```bash
uvicorn tourdata_mirror.api.main:app --reload
```

Verify the API is running:

```bash
curl http://localhost:8000/health
# {"status":"ok"}

curl http://localhost:8000/ready
# {"status":"ready","database":"ok"}
```

## Start the MCP Server

The MCP server gives LLM clients, including Claude Code and Claude Desktop, read-only access to the mirror's 20+ tools for trips, bookings, feedback, aggregates, alerts, and reference data.

```bash
pip install -e ".[mcp]"
tdm-mcp
```

This starts a stdio MCP server. See the [MCP Server documentation](tourdata-mirror/mcp-server) for client configuration and the full tool list.

## Run Tests and Lint

Before committing, run the full test suite and linter:

```bash
ruff check . && ruff format --check . && pytest
```
